# HTTP の JSON を json v2 へ替える手引き

goutil の `webframework` を使うプロダクトが、HTTP の JSON を `encoding/json/v2` へ替えるときの進め方です。替えた後に「意図しない変化が無い」と言える状態を、本番を替える前に作ることを目的にしています。

要点は 3 つです。

- PR を 3 つに分けます。無関係な整理、v1 のままで差を出す試験、本番の切り替えの順です。切り替えの PR は設定の 1 行と、その結果の直しだけにします。
- 本番を替える前に、同じ要求を v1 と v2 の app へ送って応答を比べる試験を作ります。差は 1 件ずつ「採る」か「直す」かを決め、一覧として残します。
- 切り替えの PR では、実バイナリの結合テスト、画面の E2E、外のクライアント(端末の agent など)の E2E を v2 で通してから merge します。

## 進め方

1. **無関係な整理を先に出す。** lint の自動修正(modernize など)のような大きな機械的な差分は、JSON の PR と混ぜません。差の試験の結果を読むときに、どの変化が JSON から来たのかが分からなくなります。
2. **差を出す試験の PR(本番は v1 のまま)。** 次を入れます。この PR では本番の挙動を変えません。
   - JSON のオプションを 1 か所で決めるパッケージ。
   - 試験の app も同じ設定で作る仕組み。
   - v1 と v2 の差の試験と、差の一覧。
   - v1 でも v2 でも意味が同じになる直し(`omitzero` など)。
3. **本番の切り替えの PR。** 本番の設定を v2 にし、関門(後述)を通します。差の試験などの移行のための道具は、この PR で消します。

## goutil での設定

`AppSettings.JSONOptions` にオプションを渡すと、Fiber の `JSONEncoder` と `JSONDecoder` が v2 になります。渡さなければ v1 のままです。使い方は [README](../README.md)「JSON を json v2 で読み書きする」にあります。

- **v2 の既定は `[]json.Options{json.DefaultOptionsV2()}` です。** 1 つずつ外していく形(`DefaultOptionsV1()` に v2 の挙動を足す)もできます。ただし、どこまで替えたかを後で追いにくくなるので、決められるなら v2 の既定に一度で揃える方が簡単です。
- **map の順番は固定しない方を勧めます。** v2 の既定(`Deterministic(false)`)では、map の順番が書き出すたびに変わります。固定すると、画面や試験が順番に頼っても気づけません。固定しなければ、順番に頼る試験は v2 で流した時点で落ちます。順番に意味がある物は配列で返します。
- 固定するときは、`json.Deterministic(true)` を `DefaultOptionsV2()` より後ろに置きます(後ろのオプションが勝ちます)。
- **オプションは読み込みと書き出しの両方に効きます。** 例えば `StringifyNumbers` を足すと、要求の数値を文字列で受けるだけでなく、応答の数値も文字列になります。

## v2 で変わること

Go 1.27 で確かめた違いです。左の列の変化ごとに、切り替えの前にやる事を決めます。

| 変化 | 起きうる害 | 切り替えの前にやる事 |
|---|---|---|
| 読み込みのキーの照合が、大文字・小文字を区別する | クライアントが `Name` のように違う形で送っている値が、黙って捨てられる。必須の項目なら 400 になる | 外のクライアントが送るキーを、受けの型のタグと突き合わせる(後述の「外のクライアントの本文」) |
| 同じキーが 2 回ある本文は誤り | 今は通っている本文が 400 になる | 差の一覧に載せて採る(どちらの値を使うか曖昧な本文を断る方が安全) |
| nil の slice は `[]`、nil の map は `{}`、nil の `[]byte` は `""` で書き出す | 画面の `v-if="x"` のように真偽で見ている所が、`[]`・`{}` を「ある」とみなして表示が変わる | 画面で、該当する項目の真偽の判定を探して直す。差の試験で、どの応答のどの項目かを出す |
| 数値・真偽値の `omitempty` は、ゼロでも書き出す | 今は省いている `0` や `false` が応答に出る | 数値・真偽値の `omitempty` を `omitzero` に替える。v1 でも意味は同じなので、差の試験の PR に入れられる |
| `time.Duration` は既定の書き方が無く、誤りになる | 応答が 500 になる | JSON に出す型に `time.Duration` が無いかを探し、秒の数値などに替える |
| 不正な UTF-8 を含む文字列は誤り | 今は通っている本文が 400 になる | 多くの場合は採ってよい。外から届く生のデータを JSON に詰め直している所だけ確かめる |
| HTML の文字(`<`、`>`、`&`)をエスケープしない | 応答を HTML に埋め込んでいる所があれば危ない | JSON の応答を HTML に埋め込んでいないかを確かめる |
| 誤りの文が変わり、入力の値の一部や Go の型の名前を含むことがある | `err.Error()` をそのまま応答に載せていると、送られた値が応答と利用側のログに残る | 読み込みの誤りは、値を含まない固定の文で返す(後述) |
| 未知のキーは、v1 と同じく既定では無視する | 変化は無い | 未知のキーを拒む読み込みは、自分で `RejectUnknownMembers(true)` を足す |

## 設定が届かない所を数える

Fiber の `JSONEncoder` と `JSONDecoder` を通る経路だけが替わります(README に一覧があります)。次は替わらないので、1 つずつ「揃えるか、v1 のまま残すか」を決めます。数えるときは、関数の名前で grep し、呼ぶ所の数まで出します。名前から用途を推測して範囲を狭めないでください。

- **自前の厳しい読み込み。** `json.NewDecoder` と `DisallowUnknownFields` で本文を読む関数は、v1 のままです。HTTP の本文を読むなら、同じ設定に従わせます。
- **HTTP 以外の入力。** AI のツールの引数のように、同じ関数で HTTP 以外の JSON も読んでいるときは、その呼び出しを HTTP の設定から外します。HTTP の切り替えで、別の契約まで変わらないようにするためです。
- **直接 `encoding/json` を呼ぶ所。** ETag の元にする本文、ログの生の JSON、WebSocket と NDJSON の自前の読み書き、誤りの本文の書き直しなどです。
- **SharedStorage に保存済みのデータ。** 替えた後に読み戻せるかを確かめます。

## 試験の作り方

### 設定を 1 か所で決める

本番の app と試験の app が同じ設定を使うように、オプションを返すパッケージを 1 つ作ります。試験の app も、直接 goutil から作らずに、そのパッケージの設定を渡す関数から作ります。

```go
// 本番の設定。nil なら v1
var production []json.Options

func Options() []json.Options {
	if testing.Testing() { // 試験のバイナリの中だけ、環境変数でモードを替えられる
		switch os.Getenv("APP_TEST_JSON") {
		case "v1":
			return nil
		case "v2":
			return []json.Options{json.DefaultOptionsV2()}
		}
	}
	return production
}
```

- 環境変数を読むのは `testing.Testing()` の内側だけにします。本番のバイナリに切り替えのスイッチを残しません。
- goutil の app を直接作る呼び出しは、lint で止めます。golangci-lint の forbidigo で `analyze-types: true` にし、`pkg` に goutil の import path を書きます。`pattern` は import path ではなく、呼び出しに使う**パッケージ名**(例: `^gw_web\.NewApp.*$`)で書きます。本番の app と試験の app を作る 2 つのファイルだけ、除外に入れます。

### 試験の全体を両方のモードで流す

- `APP_TEST_JSON=v2 go test ./...` で、既存の試験をすべて v2 で流します。応答を文字列のまま比べている試験は、map の順番で落ちます。読み込んでから比べる形に直します。
- **設定が本当に効いているかを確かめるカナリアの試験**を置きます。環境変数を読み損ねていると、両方のモードで同じ v1 が流れても気づけません。v1 と v2 で結果が違う本文(大文字のキーなど)を試験の app に送り、今のモードの結果になることを確かめます。

### v1 と v2 の差の試験

同じ DB に同じ要求を、v1 の app と v2 の app へ送り、応答の差を一覧(golden のファイル)と比べます。一覧は「v2 へ替えると変わる契約」そのものになるので、1 行ずつ採るか直すかを決めます。

比べ方の約束です。

- 無視してよいのはキーの順番だけです。`null`・`[]`・`{}`・欠落はすべて区別します。数値は `UseNumber` で読み、桁まで比べます。数値と文字列も区別します。
- status と Content-Type は常に比べます。本文が毎回変わる応答でも、status の差は隠しません。
- 毎回変わる値(時刻・生成した ID・token)の扱いは、範囲を狭く取ります。
  - 読む API では、v1 を 2 回流して違った所だけを「比べない」とし、一覧に `(not compared)` として出します。黙って捨てません。
  - ID・時刻らしい文字列を同じとみなすのは、書く API の応答だけにします。
- 一覧を安定させるため、配列の添字は `[*]` に、パスの中の UUID は `<id>` に置き換えます。
- JSON の後ろに余計なデータがあれば、差として扱います。

網羅の約束です。

- GET のルートは、ルーターから全部を取り出し、試しの ID を入れて送ります。ただし試しの ID が合わず、エラーの応答しか比べていないルートが多く出ます。**200 を一度も返さないルートは `(no 200)` として一覧に出し**、網羅を多く見せないようにします。
- 主な画面の読み取りは、正しい組の引数で別に送り、v1 で 200 になることを確かめます。
- 書く API では、画面と同じ形の本文に加えて、壊れた本文・重複したキー・大文字のキー・型の違う値を送ります。両方のモードで同じ失敗になる本文も 1 つは入れ、誤りの応答が揃っていることを確かめます。
- v1 と v2 は同じ DB に順に書くので、片方の結果がもう片方に混ざりえます。本文にモードの名前を入れて送り、各モードの書き込みの直後に、保存した値がそのモードの物かを確かめます。
- 試験の準備のデータは合成で作ります。実データを含む seed は使いません。そのため行の無い表の項目(要素の中の nil の slice など)の差は出ません。何が見えないかを PR に書き、切り替えの PR の E2E で補います。

この試験に特有の落とし穴です。

- **設定を読む時が経路で違います。** Fiber のエンコーダーは app を作った時に決まりますが、自前の厳しい読み込みは呼ばれた時に設定を読みます。1 つのプロセスで 2 つのモードを比べると、v1 の app への要求でも v2 で読んでしまいます。要求を送る前に、送り先の app のモードへ設定を合わせます。
- **timeout の後もハンドラーは動き続けます。** 408 が返った要求のハンドラーが、次の試しのモードで設定を読むことがあります。408 が出たら試験を止めます。
- app を作る関数が DB の接続を開き直すなら、両方の接続を閉じます。

### 外のクライアントの本文

端末の agent(Rust の serde)のような外のクライアントは、v2 の大文字・小文字の区別で最も壊れやすい相手です。

- クライアントの型から、送る本文の形をそのまま写します(serde の `rename_all` を当てた後のキー名)。
- その本文を、本番と同じ設定の試験の app の `BodyParser`(と自前の厳しい読み込み)へ通し、受けの型へ読み込みます。読み込んだ値を v1 で書き出し直し、送ったキーと値がすべて残っているかを比べます。数値は桁まで、型も含めて比べます。`None` が `null` で届く場合も入れます。
- クライアントが送るが、サーバーが保存しないキーは、その試しの中で名前を挙げて除きます。黙って捨てません。
- 中で名前の無い struct として書いている受けの型は、試験から参照できるように名前を付けます。
- 生の本文を受ける経路(ログの一括送信など)は対象の外です。その旨を書きます。

### 静的な棚卸し

`BodyParser` と `BindJSON` に渡している型を `go/packages` で全部集め、export された項目に json タグが無い物を出します。タグが無い項目は v1 では大文字・小文字を無視して一致していたので、v2 で黙って値を失います。

## 読み込みの誤りの文

v2 の誤りの文は、入力の短い文字列や数値、Go の型の名前、入力から作ったパスを含むことがあります。`err.Error()` をそのまま応答の message に載せると、送られた値(秘密の値の経路なら秘密そのもの)が応答と、それを拾う利用側のログに残ります。

- status・誤りの code・どこの誤りか(`body` など)は保ち、message は値を含まない固定の文にします。例えば、壊れた JSON、未知のキー、重複したキー、型の違う値の 4 つに分けます。
- 同じ入力なら v1 と v2 で同じ文になるように作ると、差の試験で誤りの応答も比べられます。
- `BodyParser` の誤りを `err.Error()` のまま載せている所も、切り替えの PR までに同じ扱いにします。

## 本番を替える PR の関門

本番の設定を v2 にした状態で、次をすべて通してから merge します。

- **実バイナリの結合テスト。** 試験のモードの環境変数は試験のバイナリの中でしか効かないので、ビルドしたバイナリを叩く結合テストは、本番の設定を替えた時にだけ v2 で流れます。
- **画面の E2E の全件。** 画面が送るキーの大文字・小文字と、`[]`・`{}` になった項目の表示を見ます。
- **外のクライアントの E2E。** 配布済みの古い版のクライアントが残るなら、その版でも確かめます。

同じ PR で、次も行います。

- カナリアの試験の期待を v2 に替える。
- 差の試験・差の一覧・試験のモードの環境変数・設定の上書きの関数を消す(残すと、API を足すたびに一覧の書き直しが要るだけになる)。
- 差の一覧で「直す」と決めた画面の条件を直す。

残す物は、設定を 1 か所で決めるパッケージ、試験の app を作る関数、lint の規則、外のクライアントの本文の試験です。

## lint の道具の注意

- Go 1.27 では golangci-lint v1 系が動きません(v1.64.8 は panic します)。v2 系を使い、設定も v2 の形式に書き直します。
- modernize の `omitzero` の解析は、struct の項目の `omitempty`(v1 では効いていない)を `omitzero` に自動で替えます。今は出している空の struct を省くようになり、出力が変わるので、外しておきます。`omitzero` への置き換えは、数値・真偽値の項目だけ手で行います。
